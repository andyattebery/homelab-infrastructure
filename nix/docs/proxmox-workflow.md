# Proxmox Template and Host Provisioning

## Prerequisites

- NixOS minimal ISO uploaded to Proxmox storage, matching the release `flake.nix` tracks
  (`nixos-26.05` as of writing — check `nixpkgs.url` rather than trusting this line)
- SSH public keys populated in the repo (`scripts/populate-secrets-from-op.sh`)

## Creating the template

### 1. Create a VM in Proxmox

| Setting | Value |
|---|---|
| BIOS | OVMF (UEFI) |
| EFI Disk | Add, Pre-Enroll keys **unchecked** (Secure Boot off -- NixOS ISO is unsigned) |
| Machine | q35 |
| SCSI Controller | VirtIO SCSI single |
| Disk | SCSI, 64 GiB, Discard on, SSD emulation on, IO thread on |
| CPU | host |
| Memory | 4096 MiB, Ballooning off |
| Network | VirtIO |
| Qemu Agent | Enabled |

### 2. Boot the ISO and run the install script

From the NixOS live environment console:

```sh
curl -L https://raw.githubusercontent.com/andyattebery/homelab-infrastructure/main/nix/scripts/install-proxmox-template.sh | sudo sh
```

The script partitions the disk (GPT + ESP), clones the repo, copies the generated `hardware-configuration.nix` into it, and runs `nixos-install --flake .#proxmox-template`.

### 3. Post-install

1. Remove the ISO from the VM's CD drive in Proxmox
2. Reboot
3. Verify SSH: `ssh root@<vm-ip>`
4. Push the hardware config from the VM (requires git SSH access or HTTPS token):
   ```sh
   cd /root/homelab-infrastructure
   git add nix/hosts/proxmox-vm-hardware.nix
   git commit -m "add proxmox hardware config"
   git push
   ```
   Alternatively, scp the file to your Mac and commit from there:
   ```sh
   scp root@<vm-ip>:/root/homelab-infrastructure/nix/hosts/proxmox-vm-hardware.nix nix/hosts/
   ```
5. Shut down the VM
6. Right-click in Proxmox → **Convert to Template**

## Provisioning a new host

### 1. Clone

In Proxmox: right-click template → Clone → full clone, set the VM name. Start the VM.

### 2. Provision (from Mac)

```sh
nix/scripts/add-host.sh --proxmox --tailscale --target root@<host-ip> <hostname>
```

This single command:
1. Generates the host's age key locally, stores it in 1Password, and installs it over SSH at
   `/var/lib/sops-nix/key.txt`
2. Creates `nix/hosts/<hostname>/default.nix` — which is what registers the host, since
   `nixosConfigurations` and `deploy.nodes` are both derived from the `hosts/` directory. `flake.nix`
   is not touched.
3. Adds the key to `.sops.yaml` in both required places and re-encrypts `secrets.yaml`

It runs no git commands. Stage and commit the result yourself, then deploy:

```sh
nix/scripts/nix-shell.sh flake check
nix/scripts/deploy-host.sh <hostname>
```

`vars.nix` is baked into the derivation at eval time, so nothing needs copying to the host.

## Disk resize

Resize the VM disk in the Proxmox UI, then reboot. `proxmox-guest.nix` sets
`boot.growPartition = true`, so the root **partition** expands to fill the new size.

**The filesystem does not follow automatically.** `fileSystems."/".autoResize` is not set anywhere in
this repo — `grep -rn autoResize nix/` finds only this document. So after the reboot the ext4
filesystem is still the old size and has to be grown by hand:

```sh
sudo resize2fs /dev/sda2      # check the device with: findmnt /
```

An earlier version of this page claimed `autoResize` handled it. If you would rather it were
automatic, adding `fileSystems."/".autoResize = true;` to `proxmox-guest.nix` is the change — note it
affects every Proxmox guest and so alters their system derivations.

## VM hardware config

`hosts/proxmox-vm-hardware.nix` is a shared hardware config for all Proxmox VMs with the same disk/NIC setup. It's generated by `nixos-generate-config` during template creation and committed to the repo. Host configs import it:

```nix
imports = [ ../proxmox-vm-hardware.nix ../../modules/proxmox-guest.nix ];
```

The two modules split as follows, and it is worth knowing which does what:

- `proxmox-vm-hardware.nix` — generated by `nixos-generate-config`: the virtio/AHCI initrd modules,
  the root and `/boot` filesystems by UUID, and `nixpkgs.hostPlatform` as a `mkDefault`.
- `proxmox-guest.nix` — the qemu-guest profile, `services.qemuGuest.enable`, `boot.growPartition`,
  and the grub/EFI settings (`efiSupport`, `efiInstallAsRemovable`, `device = "nodev"`).

Neither sets a serial console, despite what an earlier version of this page said.
